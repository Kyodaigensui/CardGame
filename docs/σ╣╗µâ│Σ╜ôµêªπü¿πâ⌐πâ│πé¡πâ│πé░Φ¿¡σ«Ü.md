# CardGame：アカウント・編成同期・幻想体戦ランキングの設定

## モードの分離

### アカウントモード

- ユーザー名とパスワードで登録・ログインします。
- アカウントIDに、デッキ1・デッキ2と、それぞれの幻想体カード階層を紐づけて保存します。
- デッキ構築画面で変更した編成は、両方のデッキが15枚にそろっているときに自動保存されます。アカウントホームから手動保存もできます。
- 幻想体戦の討伐記録は、サーバー側で確定したアカウントIDとユーザー名に紐づきます。
- 血の風呂・熱望する心臓・氷の女王は別々のランキングです。同じアカウントでは、ボスごとに最も少ない討伐ターン数を表示します。
- オンライン対戦もアカウントモードから利用できます。

### 一台モード

- 同じ端末で2人が交代して対戦するためのモードです。
- ログインやGoogle連携は必要ありません。
- 編成とプロフィールはメモリ内だけに保持します。ブラウザの保存領域にもGoogleスプレッドシートにも保存しません。
- ページを再読み込みすると、一台モードで作成・編集した編成は消えます。
- 一台モードではオンライン対戦・幻想体戦ランキングは利用できません。

## GoogleスプレッドシートとApps Scriptの設定

### 1. スプレッドシートを作成する

1. Googleスプレッドシートで新しいシートを作成します。
2. 名前は任意です。空のスプレッドシートを使ってください。
3. **拡張機能 → Apps Script** を開きます。

### 2. `Code.gs` を更新する

1. このプロジェクトの `google-apps-script/Code.gs`、または別途配布された `Code.gs` を開きます。
2. Apps Scriptエディタ内の既存コードをすべて置き換えます。
3. 保存します。

初回登録・ログイン・編成保存が成功すると、次のシートが自動作成されます。

- `アカウント`：アカウントID、ユーザー名、ソルト、パスワードハッシュ、デッキ2つ、幻想体階層、日時
- `討伐記録`：日時、アカウントID、ユーザー名、幻想体ID、幻想体名、ターン数

**パスワードそのものは保存しません。** ソルトと反復ハッシュを保存します。

### 3. ウェブアプリとして公開する

1. 右上の **デプロイ → 新しいデプロイ** を選びます（すでに公開済みの場合は **デプロイ → デプロイを管理 → 編集** で新しいバージョンを公開してもかまいません）。
2. 種類は **ウェブアプリ** にします。
3. 「次のユーザーとして実行」は **自分** にします。
4. 「アクセスできるユーザー」は、利用可能な場合 **全員** にします。ログイン画面へ転送される公開設定では、ゲームからのJSONP通信が完了しません。
5. デプロイし、表示された **ウェブアプリURL** をコピーします。通常、URLは `https://script.google.com/macros/s/.../exec` で終わります。

学校・職場などのGoogle Workspaceで「全員」が選べない場合、管理者のポリシーによって公開できない可能性があります。そのアカウントではこの方式が動作しないことがあります。

### 4. ゲームにURLを設定する

1. GitHub Pagesのゲームを開きます。
2. 最初の「アカウントモード」画面で、Apps ScriptのウェブアプリURLを入力します。
3. **URLを保存** を押します。
4. 新しいアカウントを作成するか、すでに作成したアカウントでログインします。

ログイン後、アカウントホームからデッキ構築・幻想体戦・オンライン対戦を利用できます。登録ができない場合は、URLが `/exec` で終わっているか、Apps Scriptを保存したか、最新バージョンをデプロイしたか、「アクセスできるユーザー」が適切かを確認してください。

## アカウントの仕様と注意

- ユーザー名は2〜12文字、パスワードは8〜100文字です。
- パスワードはスプレッドシートに平文で保存せず、ソルト付きの反復SHA-256ハッシュとして保存します。
- ログイン用のセッショントークンはブラウザに保存され、サーバー側のキャッシュによる有効期限は最長6時間程度です。期限切れの場合は再ログインしてください。
- ログイン失敗が続くと、同じユーザー名への試行を一時的に制限します。
- パスワードを忘れた場合のメール再設定機能はありません。忘れないよう安全な場所に控えてください。
- ランキング表示用の `ranking` APIは公開情報として扱われます。ユーザー名と討伐ターン数は、ウェブアプリURLを知る人が取得できます。スプレッドシート本体を公開共有する必要はありません。
- ブラウザから送られる討伐結果なので、強い不正対策ではありません。厳密に不正な記録を防止するには、信頼できるサーバーで戦闘そのものを検証する必要があります。
- 以前の匿名ランキングはアカウントIDがないため、自動では新ランキングに移行されません。新しい `討伐記録` シートにアカウントモードでの討伐が記録されます。

## 更新手順

`Code.gs` を変更しただけでは、公開中のウェブアプリに反映されません。変更後は必ず **デプロイ → デプロイを管理 → 編集 → バージョン：新バージョン → デプロイ** を行ってください。既存のデプロイを更新する場合、通常は同じウェブアプリURLを使い続けられます。
